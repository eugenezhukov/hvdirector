# Виртуальные раутеры (упрощённый аналог Cloud Director Edge)

У каждой организации может быть один виртуальный раутер: ВМ с Debian 13, которая разворачивается в ресурсах
организации (расходует её квоты vCPU, RAM, диска и числа ВМ). Раутер соединяет сети организации с внешней
(WAN) сетью провайдера, выполняет фильтрацию (firewall) и трансляцию адресов (SNAT/DNAT). VPN пока не реализован.

## Устройство раутера

```
             ┌───────────────────── ВМ раутера (Debian 13) ─────────────────────┐
 OOB mgmt ───┤ mgmt0  198.51.100.21/24   глобальная таблица (SSH от HV Director) │
 VLAN 2001   │                                                                  │
             │ ┌──────────────── VRF "vrf-tenant" (table 100) ────────────────┐ │
 WAN ────────┤ │ wan0   203.0.113.2/24, .3, .4 …   default → 203.0.113.1      │ │
 VLAN 2000   │ │ lan0 (trunk) ─┬─ vl100  192.168.100.1/24  (сеть web)         │ │
 trunk ──────┤ │               └─ vl101  10.0.1.1/24       (сеть db)          │ │
             │ └──────────────────────────────────────────────────────────────┘ │
             │ nftables: inet hvd_filter (input/forward), ip hvd_nat (DNAT/SNAT) │
             └──────────────────────────────────────────────────────────────────┘
```

* **mgmt0** — управление «в глобале»: адрес из management-сети провайдера, маршрут по умолчанию через её шлюз.
  Через этот интерфейс HV Director настраивает раутер по SSH. Пересылка между mgmt0 и сетями тенанта запрещена.
* **VRF `vrf-tenant`** — WAN и все сети организации. Адресация тенанта не пересекается с management, даже если
  подсети совпадают.
* **lan0** — адаптер Hyper-V в режиме trunk (`Set-VMNetworkAdapterVlan -Trunk`), разрешены VLAN подключённых
  сетей. Для каждой сети в ОС создаётся VLAN-интерфейс (SVI) `vl<VLAN>` с адресом шлюза сети.
* **wan0** — адаптер в режиме access VLAN внешней сети, на нём настраиваются все выделенные организации WAN-адреса.
* Конфигурация описана файлами systemd-networkd (`/etc/systemd/network/*-hvd-*`) и `/etc/nftables.conf`.
  Изменения применяет скрипт `/usr/local/sbin/hvd-apply`: проверяет синтаксис nftables, переключает сети,
  удаляет лишние VLAN-интерфейсы и загружает правила атомарно.

## Что настраивает провайдер

1. **Внешние сети** (Инфраструктура → Внешние сети):
   * WAN — VLAN, подсеть, шлюз, DNS (например, `Internet-MSK`, VLAN 2000, `203.0.113.0/24`, шлюз `.1`);
   * Management (OOB) — VLAN, подсеть, шлюз, DNS (например, `OOB-Mgmt`, VLAN 2001, `198.51.100.0/24`).
   Для каждой сети можно указать отдельный коммутатор Hyper-V (по умолчанию — коммутатор сетей тенантов кластера).
   VLAN внешних сетей не может входить в пулы VLAN организаций.
2. **Адреса организации** (Организации → карточка → «Внешние адреса»): один management IP и список WAN-адресов.
   Все WAN-адреса организации — из одной внешней сети. Адрес нельзя выдать двум организациям, шлюз сети выдать нельзя.
3. **Настройки → Виртуальные раутеры**:
   * ISO Debian 13 из общего каталога (загрузите `debian-13.x.x-amd64-netinst.iso` или `DVD-1` в «ISO-образы»);
   * размер ВМ (по умолчанию 1 vCPU, 1024 МБ, 8 ГБ);
   * зеркало Debian и HTTP-прокси для установки (для netinst обязательно; пустое поле — установка без сети с DVD-1);
   * разрешённые источники SSH на management (адрес сервера HV Director и администраторов);
   * дополнительные SSH-ключи администраторов. Здесь же показан публичный ключ HV Director.

## Сетевые требования

* Сервер HV Director должен иметь IP-связность с management-сетью раутеров (TCP 22).
* Из management-сети нужен доступ к зеркалу Debian (`deb.debian.org` или локальное зеркало/прокси), если для
  установки используется netinst ISO.
* На физических коммутаторах VLAN WAN, management и сетей тенантов должны приходить на trunk-порты узлов Hyper-V
  (тот же underlay, что для обычных сетей организаций).
* На узлах Hyper-V коммутатор (или коммутаторы, если они заданы у внешних сетей) с одинаковым именем на всех узлах.

## Развёртывание

Тенант на странице «Раутер (Edge)» нажимает «Создать раутер», выбирает класс хранилища, подключаемые сети и режим
firewall. Дальше HV Director:

1. делает копию ISO провайдера с preseed (xorriso): статический management IP, пароль root, SSH-ключ HV Director,
   **заранее сгенерированный host key раутера**, пакеты `nftables openssh-server hyperv-daemons`, полная конфигурация
   раутера; меню GRUB сразу запускает автоматическую установку;
2. создаёт ВМ поколения 2 (Secure Boot: Microsoft UEFI CA) на узле с наибольшим запасом памяти, регистрирует её
   ролью кластера (HA); порядок загрузки «диск, DVD» — после установки ВМ загружается с диска; WAN и LAN-адаптеры
   отключены, установщик видит только management;
3. ждёт, пока раутер ответит по SSH с ожидаемым host key (обычно 5–15 минут, тайм-аут в настройках);
4. извлекает и удаляет установочный ISO (в нём пароль root и закрытый host key);
5. подключает WAN (access VLAN) и LAN (trunk) и применяет конфигурацию.

Пароль root (для входа через консоль) хранится зашифрованным и виден только провайдеру («Виртуальные раутеры» →
ключ); каждый просмотр пишется в журнал аудита. Вход root по SSH — только по ключу.

## Firewall

* **Stateful** (флажок): ответный и связанный трафик разрешается автоматически (`ct state established,related`),
  правила описывают только инициирующее направление. **Stateless**: каждое направление разрешается своим правилом
  (например, ответы сервера — правилом с портом источника).
* Действие по умолчанию — «Запретить» или «Разрешить»; можно журналировать запрещённое по умолчанию.
* Правило: имя, источник, назначение, протокол (любой, TCP, UDP, TCP+UDP, ICMP), порты назначения и источника
  (номера и диапазоны: `80, 443, 8000-8100`; понятия «сервис» нет), действие (разрешить, отбросить, отклонить),
  журнал, включено. Правила применяются сверху вниз, первое совпавшее срабатывает.
* Источник и назначение — любой адрес или набор элементов: IP, подсеть, диапазон, **список IP** или **сеть
  организации** (её подсеть).
* Firewall применяется к транзитному трафику (WAN ↔ сети, сеть ↔ сеть). DNAT выполняется раньше фильтрации:
  для опубликованных сервисов в правилах указывайте внутренний адрес и порт.
* Пинг адресов раутера разрешён, SSH к раутеру из сетей тенанта и из WAN закрыт.

## NAT

* **SNAT** — исходящий доступ: внутренняя сеть или адрес → внешний IP (опционально только для заданного назначения).
* **DNAT** — публикация: внешний IP и порт или диапазон → внутренний хост и порт (опционально только для заданного
  источника). Порты задаются для TCP, UDP или TCP+UDP.
* Внешний IP выбирается из WAN-адресов организации; адрес, используемый правилами NAT, нельзя освободить.

## Диагностика

* Состояние и последняя ошибка — в карточке раутера и в «Виртуальные раутеры» у провайдера, задачи — в панели задач.
* Консоль ВМ раутера доступна провайдеру; пароль root — кнопкой с ключом.
* На раутере: `nft list ruleset`, `networkctl status`, `ip -br addr`, `ip route show vrf vrf-tenant`,
  `journalctl -k | grep hvd-` (журналируемые правила), повторное применение — кнопка «Применить заново».

## Ограничения

* Один раутер на организацию, IPv4.
* Нет VPN, DHCP-сервера, статических маршрутов и hairpin NAT (доступ изнутри к опубликованному внешнему адресу).
* Смена management IP организации при существующем раутере не поддерживается (удалите и создайте раутер заново).
